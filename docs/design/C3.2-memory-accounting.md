# C3.2 記憶體分類記帳設計(I-240 第二階段)— 第 2 版

狀態:**第 2 版草案,待 Codex 再審**。第 1 版的審查見 `tests/static/REVIEW-C32-DESIGN-20261120.md`(B1~B8 與五項決定),本版逐條回應(第 9 節對照表)。
基準:`4d5bfa1`。本文件只是設計,沒有產品程式碼變更。

## 0. 與第 1 版最大的差別

第 1 版在 pmm 之外另算一套全系統總量(`user_charged + kernel_noted + slack`),Codex 的 B1 / B4 / B8 證明這條路走不通:別的模組在自己的鎖裡改變佔用量,外面的計數永遠追不上,而且來源互相重疊。

第 2 版把**實體保證**放回唯一知道真相的地方 — 頁面配置器本身:

- **實體層(pmm)**:新增「預留」(reservation)。承諾 n 頁 = 在 pmm 裡預留 n 頁;之後兌現一頁 = 從預留裡拿一頁。一般配置(kernel heap、kernel stack、ramfs、網路…)在同一把 `pmm_lk` 裡檢查「配置後空閒頁數 ≥ 底線 + 尚未兌現的預留」。kernel 再怎麼長,也只能用到預留以外的頁 — 不需要 `kernel_noted`、不需要 `KERNEL_SLACK` 常數,也沒有被動讀計數的時間差。
- **邏輯層(membudget)**:每個 domain 的配額只是「這個行程最多能承諾 / 持有多少」,保守地按物件算,**不參與實體保證**。兩層互不重複計算(B4)。

## 1. 不變量

- **P1(底線)**:任何時刻 `nfree ≥ floor`(C3.1,不變)。
- **P2(預留可兌現)**:任何時刻 `nfree ≥ floor + nreserved`。一般配置要求配置後仍成立;兌現一頁預留時 `nfree` 與 `nreserved` 同時減一,仍成立。因此**持有預留的一方拿單一頁永遠成功**(I2)。
- **P3(配額)**:每個 domain 的 `used ≤ limit`,只在正增量時檢查(保留 `sys_memlimit` 現有語意:可以調到已用量以下,已承諾的不撤銷,只拒絕之後的增加 — B7)。
- I2 只涵蓋**單頁**的兌現。多頁連續配置(kernel stack 的 5 頁、heap 擴充的 4 頁以上)一律在公開成功之前用一般配置實際取得,失敗就整個操作失敗(B6)。

## 2. 實體層:pmm 預留

`pmm_lk` 之內多一個 `nreserved`。介面:

```c
/* 預留 n 頁:檢查 nfree − n ≥ floor + nreserved(n 不溢位),成立才 nreserved += n。0 或 -E_NOMEM */
int   pmm_reserve(size_t n);
/* 放棄 n 頁尚未兌現的預留。超過 nreserved:panic(帳務錯誤,不可能由使用者觸發) */
void  pmm_unreserve(size_t n);
/* 兌現一頁預留:nreserved > 0 必定成立,配置一頁並 nreserved −= 1。
   因為 P2,只要 nreserved > 0 就一定有頁可拿;拿不到就是帳務錯誤 → panic */
void *pmm_alloc_reserved(void);
```

- 一般配置 `pmm_alloc_pages(n)` 的條件改成 `nfree − n ≥ floor + nreserved`。
- `pmm_alloc_pages_reserve`(C3.1 的應急)仍可動用底線以下,但**不可動用別人的預留**:條件是 `nfree − n ≥ nreserved`。
- 預留是全系統一個數字,但「誰持有多少」記在 membudget 的 domain 裡(第 3 節);pmm 不知道 domain。

鎖:全部在 `pmm_lk`(90)之內完成,與 C3.1 相同。kmalloc 擴充在 `heap_lk`(80)之內呼叫一般配置 → 80→90,順序合法;不需要在 heap 鎖裡拿 membudget 的鎖(B1 的 80→75 問題消失)。

## 3. 邏輯層:domain

```c
struct mb_domain;                                         /* 不透明 */
struct mb_domain *mb_domain_new(unsigned long limit);    /* refcount 1 */
int   mb_domain_get(struct mb_domain *d);                 /* refcount 溢位回傳 -E_NOMEM(不 panic) */
int   mb_domain_put(struct mb_domain *d);                 /* 回傳 1 = 這是最後一份參考,呼叫者在鎖外 kfree;
                                                             此時 used 與 tickets 必須都是 0,否則回傳 -1 並計數,
                                                             呼叫者記入黑盒子(void 介面無法讓呼叫者知道 — B 的其他要求) */
int   mb_commit(struct mb_domain *d, enum mb_class c, unsigned long pages, unsigned flags);
      /* 邏輯配額 + 實體預留在同一個操作完成:先在 mb_lk 內檢查並記配額,
         放開 mb_lk 後 pmm_reserve;預留失敗就退回配額。結果:0 或 -E_NOMEM,失敗時兩層都不變。
         (mb_lk 75 → pmm_lk 90 也合法,但為了讓 mb_lk 內不呼叫任何其他模組,分成兩步,
          中間狀態是「配額已記、預留未取」,只會讓別人提早被拒絕,不會超額) */
int   mb_charge(struct mb_domain *d, enum mb_class c, unsigned long pages, unsigned flags);
      /* 只記邏輯配額,不預留實體(用於已經實際配置好的物件:kernel stack、kmalloc 物件、ramfs 資料頁) */
void  mb_uncharge(struct mb_domain *d, enum mb_class c, unsigned long pages);
int   mb_ticket_use(struct mb_domain *d);                 /* 兌現一頁:d 的 tickets −1,並 pmm_alloc_reserved */
void  mb_ticket_drop(struct mb_domain *d, unsigned long n);   /* 放棄 n 張未兌現的票:pmm_unreserve */
```

- `used` 是所有類別合計,配額只有一個(第 1 版的單一聚合 domain 方向保留)。
- `tickets` = 這個 domain 持有、尚未兌現的預留張數;全系統 `nreserved = Σ tickets`(debug 建置在每次操作後核對)。
- `mb_lk`(75)內只做加減比較;超量 uncharge 在 debug 建置 panic,release 建置夾到 0 並回傳 -1 讓呼叫者記入黑盒子。

## 4. 承諾與兌現:什麼時候拿票、什麼時候用票

| 情況 | 邏輯配額 | 實體預留(票) | fault 時 |
|---|---|---|---|
| sbrk / mmap n 頁 | ANON +n | +n + `pt_need(範圍)` | 用一張票配置資料頁;需要新的頁表時用一張票 |
| 建立執行緒(stack) | STACK +255 | +255 + `pt_need(slot)` | 同上;255 = 1MB 減保護頁,含原本先對映的 4 頁(B7 決定) |
| exec 映像的私有頁 | IMAGE +k | 映像建立時**直接配置**(用票配置),不留未兌現的票 | — |
| fork 子行程 | 子 domain:ANON + STACK + IMAGE = 父的承諾總量;KOBJ = 子行程物件 | +(父的承諾總量)+ 子的根表與中間表(見第 6 節) | COW 寫入:用一張票複製 |
| kernel stack、行程結構、執行緒結構、frame、檔案、管線 | KOBJ +(kmalloc 實際配置大小向上取整成頁,含標頭) | 不預留:物件在公開成功之前用一般配置實際取得 | — |
| ramfs 資料頁、區塊表、inode、目錄項 | FS domain +n | 不預留:寫入時一般配置 | — |

**歸還時,票不能多退**(否則還在共用的頁沒有票可複製)。munmap / sbrk 縮小 / 結束時逐頁:

- 該頁還沒配置(未兌現)→ 退一張票。
- 已配置且 refcount > 1(與別人共用的 COW 頁)→ 退一張票(不再需要複製),放掉參考。
- 已配置且只有自己 → 釋放那一頁,不退票。

COW 時另一方先複製走、讓這一頁變成只有自己,而自己手上那張票沒用到:這是**保守的多餘票**,直到結束或 munmap 才退。安全(只會讓別人提早被拒絕),不會超額。

### 頁表的票(B3)

`pt_need(範圍)` = 範圍跨到的每一層中間表數量(最壞情況,假設都還不存在),在承諾時一起預留,記在**位址空間**的 `pt_tickets`。`walk` 建新表時從 `vs->pt_tickets` 用一張;已存在就不用。兩個承諾都替同一張還不存在的表預留了票 → 多餘的票留在空間上,`vm_space_destroy` 時一次退回。munmap 不釋放中間表,也不退頁表票(它們在 destroy 時一起處理)。

`walk` 因此需要知道「這是哪個位址空間」:介面由 `(root, user)` 改成傳 `struct vm_space *`(kernel 空間傳 NULL = 不用票、一般配置)。根表在 `vm_space_create` 用一般配置實際取得(建立失敗就回傳 NULL,既有路徑)。`split_large` 只發生在 kernel 空間,不涉及使用者的票。

## 5. 誰持有 domain 的參考(B5)

| 持有者 | 何時取得 | 何時放掉 | 記在 domain 的什麼 |
|---|---|---|---|
| 行程 `struct proc` | 建立 / fork | `proc_free_list`(wait 回收 zombie 時) | ANON、KOBJ(行程結構本身) |
| 位址空間 `struct vm_space` | `vm_space_create(dom)` | `vm_space_destroy` 退完票與配額之後 | STACK、IMAGE、PGTABLE 的配額與票 |
| 執行緒 | `thread_create` 之前 | `thread_free`(切換後由延遲回收執行) | KOBJ(kernel stack 5 頁、執行緒結構) |
| 檔案 `struct file`、管線 | 建立時取得**建立者**的 domain | 最後一個參考釋放時 | KOBJ |
| ramfs | 開機時建立的 FS domain,永久 | — | RAMFS |

- **exec 不換 domain**:domain 代表「這個行程」,exec 之後仍是同一個行程。這樣 fork 前建立、exec 後仍共用的管線,繼續算在同一個 domain 上,不會出現「exec 一次就得到一份全新額度」的漏洞(B5 的 IPC 繞過問題)。
- 執行緒結構進永久的 thread pool、kernel stack 進快取時:先 `mb_uncharge`,配額退回;實體頁仍是 kernel 的(在 pmm 看來是已配置的頁,不在預留裡,所以不影響 P2)。
- 父行程結束而子行程仍持有它建立的管線:管線持有父 domain 的參考,父 domain 在管線釋放之後才歸零、釋放。

## 6. 交易

### exec(B2)

domain 不換,所以沒有「新 domain 的 limit」問題。交易期間同一個 domain 暫時同時持有新舊兩份:

```
1. 在 p->mem.mx 之內:pending = 舊空間記在 domain 上的 STACK + IMAGE + PGTABLE 配額
   (exec 成功後會歸還的部分;ANON 也會歸還,一起算進 pending)
2. 建新空間 vm_space_create(D);image_build 的每一筆 mb_commit / mb_charge 帶 MB_F_EXEC,
   配額檢查改為 used + n ≤ limit + pending(最終仍 ≤ limit,只有交易中暫時超過)
   實體預留照常(新舊兩份是真的同時佔用,P2 不放寬)
   任何一步失敗 → vm_space_destroy(新空間)退回它記的一切 → 回傳錯誤;舊程式與帳務完全不變
3. ---- 從這裡起不會失敗 ----
   在 sched_lock 之內發布 p->space(保留現有讀者同步:sys_procinfo)
4. 歸還舊 ANON(依第 4 節逐頁規則退票)、thread_set_space(新)、vm_space_destroy(舊)
   → 舊空間的頁實際釋放之後,它的票與配額才退回
```

例:L = 100,舊程式用 80(全部會歸還),新映像要 80 → 交易中 used = 160 ≤ 100 + 80,通過;結束時 80。新映像要 101 → 拒絕,舊程式不動。

### fork

```
1. 子 domain C = mb_domain_new(父 limit);失敗 → -E_NOMEM
2. 預先取得子的一切(都還沒公布):行程結構、fork_start、frame、kernel stack 與執行緒結構(thread_prepare,不排入執行)
3. mb_commit(C, 父的承諾總量 + 子空間的根表與中間表最壞數量)
4. vm_space_fork(父, C):建表用 C 的頁表票
5. ---- 從這裡起不會失敗 ----
   公布 pid,thread_start(第 2 步準備好的執行緒)
```

現在的 `sys_fork` 先公布 pid 再 `thread_create`,失敗時留下一個立刻死亡的子行程(B 的其他要求);改成先準備後公布,`thread_create` 拆成 `thread_prepare` / `thread_start`(準備時已經取得 stack 與結構,start 只排入佇列,不會失敗)。

### 建立執行緒

`mb_commit(D, STACK, 255 + pt_need)` → `thread_prepare` → 對映初始 4 頁(用票)→ `thread_start`。任一步失敗依反序退回。

## 7. 分區表(B4):每一頁實體記憶體屬於哪裡

| 分區 | 範圍 | 計數來源 | 備註 |
|---|---|---|---|
| 開機基準 | t0 以前配置的一切(kernel 映像、位元圖、開機頁表、C3.1 取樣前的結構) | `usable = free(t0)` 之外 | t0 = C3.1 的取樣時點,不再另外扣 |
| 底線 | `floor` 頁 | pmm | 只有應急配置能用 |
| 預留 | `nreserved` 頁(尚未兌現的承諾) | pmm,= Σ domain.tickets | 一般配置不能用 |
| 已配置 | 其餘所有已配置頁:使用者資料頁、使用者與 kernel 頁表、kernel heap(含 KOBJ 與 ramfs metadata)、kernel stack(使用中與快取)、ramfs 資料頁、檔案共用頁 | pmm 的 bitmap | 每一頁只在 bitmap 記一次,沒有第二套計數 |
| 空閒 | 其餘 | pmm | |

邏輯配額(KOBJ 取整、STACK 255、ANON 的範圍)只用來限制每個 domain,**不拿來推論實體用量**;實體的唯一真相是 pmm 的 bitmap 與 `nreserved`。共用的程式碼頁屬於檔案(已配置分區),不計入任何 domain 的實體預留,但 domain 對檔案的參考讓它留在記憶體裡。

## 8. 驗收

- **P2 交錯**(Codex 主機探針,真 pmm.c):預留 / 兌現 / 一般配置 / kernel 擴充 / 歸還任意交錯,每一步 `nfree ≥ floor + nreserved`;持有票者兌現永遠成功;失敗不改變狀態。
- **配額邊界**:L100、舊 80、新 80 的 exec 成功;新 101 拒絕且舊程式與帳務不變;每一個可失敗步驟注入失敗。
- **I2**(三架構 QEMU):全系統飽和後,已承諾的匿名頁、整個 255 頁 stack、fork 後 COW 第一次寫入、需要新頁表的位址 — 第一次觸及都成功。
- `memhog=fork`:fork 回傳 -E_NOMEM、結束碼 0、沒有行程在 page fault 被終止。新增 `threads`、`stack`、`exec`、`maps` 模式。
- **fork / thread 失敗清理**:根表、中間表、kernel stack、frame、執行緒結構的配置各自注入失敗,不公布 pid、沒有殘留。
- **生命週期**:管線跨 fork 且父先結束、exec 保留描述符、zombie 未 wait、延遲回收、stack 快取往返 — 逐步核對 domain 參考、配額與票數。
- **帳務錯誤診斷**:溢位、非法類別 / 旗標、refcount 溢位、超量 uncharge、退票超過持有量。
- **兩種平衡分開驗**:實體 —「空閒 + 已配置 = usable」且「Σ tickets = nreserved」;邏輯 — 各 domain 結束後 used 與 tickets 歸零。
- 每一類拿掉記帳或拿掉 P2 檢查的負對照。

## 9. 對 Codex 審查的回應

| 項目 | 處理 |
|---|---|
| B1 被動統計 / 80→75 | 實體保證改為 pmm 預留,在 `pmm_lk` 內與一般配置一起判斷;heap 擴充是一般配置(80→90)。快取進出不必記帳(已配置的頁本來就不在預留裡) |
| B2 exec limit | domain 不換;交易中上限為 `limit + pending`,最終仍 ≤ limit;不需要搬移執行緒參考 |
| B3 頁表 | 承諾時連同 `pt_need` 一起預留,票記在位址空間;fault 用票;destroy 時退多餘的票 |
| B4 重複計算 | 實體只看 pmm;邏輯配額不推論實體;第 7 節分區表 |
| B5 生命週期 | 第 5 節持有者表;檔案 / 管線持有建立者 domain;exec 不換 domain,堵住 IPC 繞過 |
| B6 連續頁 | I2 只保證單頁;多頁一律公布成功前實際取得 |
| B7 memlimit / stack | 保留降低語意;stack 預付 255 頁 + 頁表 |
| B8 slack | 不再需要 slack 常數:kernel 的動態配置被 P2 擋在預留之外,超過就配置失敗(各呼叫點本來就處理 NULL) |
| 其他:fork 公布後失敗 | `thread_prepare` / `thread_start`,先準備後公布 |
| 其他:void 診斷 | put / uncharge 回傳結果,呼叫者記黑盒子 |

### 仍需 Codex 決定

1. P2 讓 kernel 自己的配置在「空閒 − 預留 − 底線」用完時失敗:使用者大量承諾而不使用時,kernel 可能比現在更早配置失敗(例如網路收不到封包)。這是「承諾必兌現」的代價。是否接受,或要求替 kernel 另保留一段一般配置專用的空間(底線之上、預留之外)?
2. 每條執行緒 255 頁 stack + 頁表的預留,以 128MB 的機器(使用者可用約 100MB)計,全系統約只能有 90 條使用者執行緒同時存在(就算它們都不用 stack)。符合 Codex 的決定,但是否要同時提供顯式的「較小 stack」建立選項(另做 API,不默默縮小)?
3. 分批:(a) pmm 預留 + domain + ANON 遷移(保留 memlimit 語意);(b) PGTABLE 票 + KOBJ + thread_prepare/start;(c) STACK + IMAGE + fork + exec;(d) RAMFS。

# 第 3 版修訂(回應 Codex 163;取代第 2 版第 2、3、4、6 節中相衝突的內容)

Codex 163 接受「預留做在 pmm 裡」的方向,並指出三項阻擋:V2-1 COW 票的歸屬、V2-2 兩步記帳的中間狀態、V2-4 底線與應急配置的不變量;另有 V2-3 exec 旗標太寬與幾處介面不一致。

## R1. 票的歸屬:每個「映射」一張,由 PTE 狀態決定(取代第 4 節的 refcount 規則)

不再用 refcount 猜誰有票。規則只看**自己這一筆映射**的狀態:

> **一筆已承諾的私有映射持有一張票,若且唯若它還不是「自己獨佔的實體頁」**:
> (a) 承諾範圍內還沒有 PTE(未兌現),或 (b) PTE 帶 `VM_COW`(與別人共用,寫入時要複製)。
> 沒有 `VM_COW` 的可寫私有 PTE = 獨佔,不持有票。

這是每筆映射各自的狀態,所以「全系統的票 = Σ 各位址空間的票 = `nreserved`」可以逐筆核對,不必知道別的位址空間做了什麼。

| 事件 | 映射的變化 | 票 |
|---|---|---|
| 承諾 n 頁(sbrk / mmap / stack) | n 筆 (a) | 這個空間 +n |
| 第一次觸及未兌現頁 | (a) → 獨佔 | 用自己 1 張(`pmm_alloc_reserved`) |
| **fork** | 父的每一筆可寫獨佔頁 → 兩邊都 (b);父原本的 (a)、(b) 照舊;子得到父每一筆 (a)、(b) 的對應 | **父 +(這次由獨佔變 COW 的頁數)**;**子 +(父的 (a) 數 + 父 fork 後的 (b) 數)** |
| COW 寫入,refcount > 1 | (b) → 獨佔(複製到新頁) | 用自己 1 張 |
| COW 寫入,refcount = 1(別人都已複製走或結束) | (b) → 獨佔(直接改回可寫) | **退自己 1 張**(`pmm_unreserve`) |
| munmap / 結束,映射是 (a) | 移除 | 退自己 1 張 |
| munmap / 結束,映射是 (b) | 移除,`pmm_free`(refcount −1) | 退自己 1 張 |
| munmap / 結束,映射是獨佔 | 移除,`pmm_free` | 不動 |

Codex 的反例逐一驗證:

- **父先 unmap**:父那筆是 (b)(fork 時父也拿到 1 張),退父自己的 1 張;子那筆仍是 (b) 持有子的 1 張。沒有下溢,也沒有動到子的票。
- **父先 COW 寫入**:父那筆 (b) 有自己的票 → 複製。子那筆仍 (b)、仍有票;之後子寫入時 refcount = 1 → 退子的票。
- **子先複製、父變成 refcount 1**:父那筆仍標 `VM_COW`、仍持有票(不是獨佔)— 與「獨佔不持票」不矛盾;父之後寫入 → 退票,或 unmap → 退票。
- **連續 fork 樹**:每次 fork 只看「父自己的映射狀態」,孫行程同理;每筆映射各自一張,總數一定等於 nreserved。

代價(保守):fork 時父也要替自己變成 COW 的頁補票,所以 fork 一個有 k 頁私有資料的行程要預留 2k 頁(父 k + 子 k)再加上子的未兌現數。在 COW 頁被寫入或釋放之前,這些票一直佔著預留。這是「每筆映射各自持票」方案的**保守**需求:兩個共用者最後分開時實際只多需要 1 頁,多出的 1 張是為了不在不同擁有者之間轉移票所付的代價(Codex 164)。fork 的順序:先建完子空間的表(會失敗的步驟),之後才把父的 PTE 改成 COW(不會失敗),避免要回滾父的 PTE、票與 TLB。

fork 的預留在複製頁表之前一次取得(父增量與子總量一起);失敗就什麼都不改,父的 PTE 也還沒被改成 COW。唯讀的私有頁(fork 不改成 COW 的)與 `VM_SHARED` 頁不持票。

## R2. 帳本與完成點(取代第 3 節的兩步 `mb_commit`)

**帳本的擁有者**(每一筆配額 / 票只屬於一個擁有者,不互相借用):

| 帳本 | 內容 | 保護它的鎖 |
|---|---|---|
| 位址空間 `vs->ledger` | 各類別配額(ANON、STACK、IMAGE、PGTABLE)、資料頁票、頁表票 | `vm_lk` |
| 行程 / 執行緒 / 檔案 / 管線 | 各自的 KOBJ 配額(物件已實際配置,沒有票) | `mb_lk` |
| domain | 上列帳本的總和 `used`、配額 `limit`、參考數 | `mb_lk` |
| pmm | `nreserved`、`nfree` | `pmm_lk` |

**鎖順序**:`vm_lk`(60)→ `mb_lk`(75)→ `pmm_lk`(90)。`mb_lk` 之內唯一會呼叫的外部函式是 pmm 的純記帳操作(`pmm_reserve` / `pmm_unreserve` / `pmm_alloc_reserved`;它們只動 bitmap 與計數,不配置 heap、不印訊息)— 這是寫明的例外,取代第 2 版的「放鎖後再預留」。

**每個操作的完成點**(linearization point;在這一刻之前失敗,一切不變):

| 操作 | 持有的鎖 | 完成點 | 完成點之後 |
|---|---|---|---|
| 承諾 n 頁 `vm_space_commit(vs, class, n)` | vm_lk → mb_lk → pmm_lk | pmm_lk 內 `nreserved += n`,同一段 mb_lk 內 `used += n`,同一段 vm_lk 內 `ledger.tickets += n` | 放鎖;對**遵守完整鎖序**的觀察者三者同時成立。單獨呼叫 pmm 的查詢函式看不到跨帳本的一致快照;debug 核對 Σ 票 = nreserved 必須在 vm_lk → mb_lk → pmm_lk 全部持有時讀(Codex 164) |
| 兌現 1 頁(fault) | vm_lk → pmm_lk | `pmm_alloc_reserved`:`nfree −1`、`nreserved −1`;vm_lk 內 `tickets −1` 並寫入 PTE | 配額不變(承諾時已記) |
| 退票 | vm_lk → pmm_lk | `nreserved −= n`、`tickets −= n` | — |
| 歸還配額 | vm_lk → mb_lk | `used −= n`、`ledger.class −= n` | — |
| fork 的預留 | vm_lk(全域一把)→ mb_lk(全域一把)→ pmm_lk | 父增量與子總量的 `nreserved` 一次加上 | 之後才改父的 PTE、建子的表 |

fault 時要用的票屬於 `vs`,由 `vm_lk` 保護,與 PTE 的修改在同一段鎖內:不會有兩條執行緒用同一張票。

## R3. 底線與應急(取代第 1 節 P1 / P2)

| 不變量 | 內容 | 何時成立 |
|---|---|---|
| **N1** | `nfree ≥ nreserved` | **永遠**(包括應急配置之後):任何人兌現預留都拿得到頁 |
| **N2** | `nfree ≥ floor + nreserved` | 沒有應急配置欠帳時成立 |

- **一般配置 n 頁**、**新的預留 n 頁**:要求配置 / 預留之後 N2 仍成立。檢查寫成不會溢位的形式:先確認 `n ≤ nfree`,再比 `nfree − n ≥ floor + nreserved`(`floor + nreserved ≤ npages`,不會溢位)。
- **應急配置 n 頁**(`pmm_alloc_pages_reserve`):只要求之後 N1 成立 — 可以吃進底線,不能吃進預留。
- **欠帳期間**(應急配置讓 N2 不成立):新的預留與一般配置一律拒絕;兌現既有預留照常成功(N1 保證);釋放頁會讓 nfree 回升,回到 N2 成立後恢復正常。
- **兌現**:`nfree` 與 `nreserved` 同時減一,N1、N2 都不會因此被破壞。

## R4. exec 的交易憑證(取代第 6 節的 `MB_F_EXEC` 旗標)

```c
struct mb_exec_txn;     /* 不透明:綁定「這次 exec 的新位址空間」與「將被銷毀的舊空間帳本」 */
int  mb_exec_begin(struct mb_domain *d, struct vm_space *old_vs, struct vm_space *new_vs, struct mb_exec_txn **out);
void mb_exec_end(struct mb_exec_txn *t);    /* 成功、失敗都要呼叫;清除放寬 */
```

- `pending` = **舊位址空間帳本的配額總和**(ANON、STACK、IMAGE、PGTABLE 都記在空間帳本上 — ANON 也改由空間持有,因為舊 heap 與對映隨舊空間一起消失)。行程結構、執行緒、kernel stack、保留下來的檔案與管線的 KOBJ **不在** pending 裡。
- 放寬只適用於「記到 `new_vs` 帳本」的承諾:其他路徑(同時建立的管線、別條執行緒的動作)記帳時照一般上限檢查。
- 檢查:`n ≤ limit + pending − used`,三個量先各自確認不溢位(`limit + pending` 若溢位視為無上限的 pending 不合法 → 拒絕)。
- **最終用量**:commit 時檢查「新空間帳本 + 其他帳本 ≤ limit」;不成立就失敗回滾(這種情況只會在交易期間有人調低了 memlimit 時發生)。memlimit 調到 used 以下仍允許(B7),之後的 exec 依這條規則可能被拒絕 — 明確寫進行為說明。

## R5. 介面修正

- `void *mb_ticket_use(...)` 回傳配置到的頁(不可能失敗;失敗 = 帳務錯誤 → panic)。

enum mb_class { MB_ANON, MB_STACK, MB_IMAGE, MB_PGTABLE, MB_KOBJ, MB_RAMFS, MB_NCLASS };

## B3. 承諾、兌現、歸還(vm 層對外的新函式)

```c
/* 承諾 [va, va+len) 的 n 頁匿名記憶體(heap 擴大、mmap)。
   鎖序 vm_lk → mb_lk → pmm_lk 之內一次完成:
     pt = pt_need(va, len)(R5:只算中間表,每一層以「範圍跨到幾個該層索引」計,假設都還不存在)
     mb_quota_add(dom, ANON, n) 且 mb_quota_add(dom, PGTABLE, pt) 且 pmm_reserve(n + pt)
     data_tickets += n,pt_tickets += pt,quota[ANON] += n,quota[PGTABLE] += pt
   任一步失敗:已做的反向撤銷(都在同一段鎖內,外面看不到中間狀態),回傳 -E_NOMEM */
int  vm_space_commit_anon(struct vm_space *vs, uintptr_t va, uintptr_t len);

/* fault:在已承諾的 va 配置一頁(內容清 0)。用 1 張資料票(pmm_alloc_reserved);
   需要新的中間表時用 pt_tickets(pmm_alloc_reserved)。票不夠 = 帳務錯誤 → panic。
   1 = 別的執行緒已經對映了(不用票) */
int  vm_space_fault_anon(struct vm_space *vs, uintptr_t va);

/* 歸還 [va, va+len)(munmap、sbrk 縮小、結束):逐頁依 R1 —
   沒有 PTE → 退 1 張資料票;VM_COW → 退 1 張並 pmm_free;獨佔 → pmm_free。
   quota[ANON] −= 頁數。頁表票不在這裡退(中間表到 destroy 才釋放)。在 vm_lk 之內做完 TLB 失效 */
void vm_space_release_anon(struct vm_space *vs, uintptr_t va, uintptr_t len);

/* destroy:釋放所有頁與表;剩下的 data_tickets、pt_tickets 一次 pmm_unreserve;
   quota 全部從 dom 退回;最後 mb_domain_put(dom) */
void vm_space_destroy(struct vm_space *vs);
```

- `walk` 改成 `walk(struct vm_space *vs, pte_t *root, ...)`:`vs` 為 NULL(kernel)時建表用一般配置;不為 NULL 時,有 `pt_tickets` 就用票,沒有就一般配置並記 PGTABLE 配額(這條路徑給還沒接上預留的 stack / 映像用,(c) 之後拿掉)。
- 哪些頁屬於 ANON:由行程記憶體模組(proc_mem.c)依位址範圍判斷 — heap `[USER_HEAP_BASE, brk)` 與 mmap 表格裡的區塊 — 它呼叫上面三個函式;vm 層不知道範圍的意義。

## B4. 行程這一側(proc_mem.c)

- `p->mem.commit` / `p->mem.limit` / 全域的 `commit_total` / `commit_cap` **移除**,改成 `p->mem.dom`(持有一份參考)。`sys_memlimit` 改呼叫 `mb_limit` / `mb_set_limit`,調高仍需 CAP_ADMIN,調低允許低於已用量。
- 全系統上限不再由 `commit_cap` 估算:預留在 pmm 裡,超過就是 `pmm_reserve` 失敗(P2)。**行為變更**:原本 commit_cap 在第一次使用時以當時空閒頁數減保留量固定下來;之後是即時的「空閒 − 預留 − 底線」。寫進行為說明與 DEVLOG。
- 鎖:sbrk / mmap 目前在 `pstate_lk`(20)之內記帳;改成在 `pstate_lk` 之內呼叫 `vm_space_commit_anon`(20 → 60 → 75 → 90,順序合法)。munmap / sbrk 縮小在 `p->mem.mx` 之內、`pstate_lk` 之外呼叫 `vm_space_release_anon`(與現在的 `vm_space_unmap` 相同位置)。
- fault:`proc_fault_locked` 的 heap / mmap 分支改呼叫 `vm_space_fault_anon`(不再 `pmm_alloc` 後 `vm_space_map_new`)。

## B5. fork 與 exec 在 (b1) 的範圍

- **fork**:子行程的 domain 與空間、ANON 票依 R1:父的每一筆 ANON 可寫獨佔頁 → 父 +1、子 +1;父的未兌現與 COW → 子各 +1;子的中間表 → `pt_need`(子的 ANON 範圍)。順序:取得 domain、空間、**全部預留**(一次)→ 複製頁表(建子的表用子的 pt 票)→ 最後才把父的 PTE 改成 COW(不會失敗)。任一步失敗:destroy 子空間(退回一切)、放掉 domain,父完全不變。stack 與映像頁照舊(沒有票),(c) 再補。
- **exec**:舊空間 destroy 時退回它的 ANON 票與配額;新程式從空的 heap 開始,沒有 ANON。交易憑證(R4)留到 (c)(那時映像與 stack 才記在新空間上)。

## B6. (b2) kernel 物件與執行緒

```c
/* 準備一條執行緒:配置 kernel stack 與結構、記 KOBJ 配額(dom 可為 NULL = kernel 執行緒),
   不排入執行。之後只能 thread_start 或 thread_abandon */
struct thread *thread_prepare(const char *name, void (*fn)(void *), void *arg, int prio, struct mb_domain *dom);
int  thread_start(struct thread *t);     /* 指定編號、排入佇列;不會失敗,回傳 tid */
void thread_abandon(struct thread *t);   /* 釋放準備好但沒啟動的執行緒,退回配額 */
```

- KOBJ 的計法:kernel stack `STACK_PAGES + 1` 頁(精確);執行緒結構、行程結構、`ustart`、`fork_start`、frame、`struct file`、管線以 `kmalloc_size()`(實際配置大小,含標頭)向上取整成頁 — 只當保守的邏輯配額(Codex 的決定 3)。
- 持有者:執行緒持有 dom 的參考直到 `thread_free`(延遲回收)— 在那裡退回 kernel stack 與結構的配額,再放掉參考;stack 進快取、結構進 pool 之後就是 kernel 的,不再算任何 domain。
- 檔案與管線:建立時取得建立者的 domain 參考,最後一個參考釋放時退回並放掉(R2 的持有者表)。
- **fork 改成先準備後公布**:`thread_prepare(子)` 放在公布 pid 之前;所有可能失敗的步驟都在公布之前完成,公布之後只剩 `thread_start`(不會失敗)— 修掉現有「公布 pid 之後 `thread_create` 才失敗,留下立刻死亡的子行程」。

## B7. 驗收

**(b1)**
- 確定性測試:承諾到 domain 配額剛好滿 / 超過 1 頁;承諾到 pmm 預留剛好滿;每一步失敗後 pmm 預留、domain used、空間帳本三者都不變。
- **I2**:全系統飽和(`memhog` 把一般配置吃到底線)之後,已經 sbrk / mmap 承諾的每一頁第一次觸及都成功,包括需要新中間表的位址;沒有行程在 fault 被終止。
- fork → 父或子先寫 / 先 munmap / 先結束、連續 fork:每一步核對「Σ 各空間 data_tickets + pt_tickets = pmm nreserved」(在 vm_lk → mb_lk → pmm_lk 全部持有時讀)。
- memlimit 調低到已用量以下:已承諾的不受影響,下一次 sbrk / mmap 被拒絕。
- 負對照:fault 不用票改用一般配置 → 飽和時被終止;歸還時「VM_COW 不退票」→ Σ 核對失敗;承諾不算頁表票 → 需要新中間表的位址在飽和時失敗。

**(b2)**
- 每一個配置點注入失敗(kernel stack、執行緒結構、行程結構、frame、空間):不公布 pid、配額與預留都回到原值。
- 執行緒結束後,延遲回收之前與之後的配額變化;stack 快取往返。
- 結束路徑在記憶體耗盡時實測(Codex 166:`stack_release` → `vm_map` 可能配置中間表)。

# 第 (b) 批介面修訂(回應 Codex 168 / 169)

Codex 169 的決定:接受 (b1)/(b2) 拆分;接受以 pmm 即時預留取代 `commit_cap`,不再加第二個常數上限;munmap 分段解除,每段最多 64 頁,整段期間持有 `p->mem.mx`,`pstate_lk` 只做短暫更新(64 不是時間保證)。以下修訂四項阻擋與附帶問題。

## BR1. 配額檢查不下溢(阻擋 1)

```c
int mb_quota_add(...n...):
    n == 0                      → 0,不改狀態
    used > limit                → -E_NOMEM(limit 曾被調低到 used 以下:不再接受任何正增量)
    n > limit − used            → -E_NOMEM(此時 limit − used 不會下溢)
    否則 used += n
```

多個類別一起記(bundle,見 BR4)時,先把各類別的量加總並檢查加總不溢位(每加一項先比 `x ≤ ULONG_MAX − sum`),再對總量做上面的檢查;exec 的放寬上限(R4)`limit + pending` 同樣先檢查溢位,溢位就拒絕。依 Codex 的建議,membudget 先做成**獨立的純計數模組**(不接任何 VM hook),交 Codex 主機窮舉驗證後再接。

## BR2. 建頁表要帶明確用途(阻擋 2)

`walk` 不再看「這個空間總共有幾張頁表票」,改由呼叫者指定用途:

| 用途 | 誰用 | 缺中間表時 |
|---|---|---|
| `WALK_KERNEL` | kernel 位址空間 | 一般配置,不記配額 |
| `WALK_LEGACY` | 還沒接上預留的 stack、映像、fork 時非 ANON 區域 | 一般配置,記 PGTABLE 配額;**不碰** `pt_tickets`;失敗照舊回報 |
| `WALK_ANON` | 已承諾的 ANON 的 fault、fork 時子空間的 ANON 區域 | **只能**用 `pt_tickets`(兌現預付);沒有票 = 帳務錯誤 → panic;**不退回**一般配置 |

已經存在的表(不論當初由哪種用途建立)任何用途都可以直接使用,不耗票。不同區域之間不能借用承諾:legacy 建表不會耗掉 ANON 預付的票,所以 ANON 之後在別處 fault 一定有票。

## BR3. VM 層如何知道哪些 COW 頁有票(阻擋 3)

現在 `proc_page_fault` 在取得 `p->mem.mx`、在判斷 heap / mmap 範圍之前,就先呼叫 `vm_space_fault` 處理任何 COW。VM 層因此必須**從 PTE 本身**知道這筆 COW 映射有沒有票,不能回頭拿 `pstate_lk`(60 → 20 會反向)。

- 新增邏輯旗標 `VM_TICKET`:只會和 `VM_COW` 一起出現,表示「這筆 COW 映射持有一張資料票」(R1 的 (b))。
- PTE 裡的編碼:三個架構的軟體位元都只保證兩個(RISC-V 的 RSW 只有 bit 8、9,已經分給 SHARED 與 COW)。但 `VM_SHARED`(屬於檔案的頁)與 `VM_COW` 本來就不會同時成立,所以用「兩個位元都設」表示 **COW + TICKET**:

  | PTE 軟體位元 | 意義 |
  |---|---|
  | 00 | 一般(獨佔,或唯讀私有) |
  | 01 SHARED | 屬於檔案的共用頁 |
  | 10 COW | 沒有票的 COW(legacy:stack、映像) |
  | 11 | COW + TICKET(ANON 的 COW,持有一張票) |

  `arch_pte_flags` 解出 11 時回傳 `VM_COW | VM_TICKET`(**不**含 `VM_SHARED`,所以 `free_table` 仍會釋放它);`arch_pte_leaf` 拒絕 `VM_SHARED | VM_COW` 的組合(KASSERT),避免誤用。
- `vm_space_fault`(COW 快路徑)看 PTE:`VM_TICKET` → refcount > 1 用自己的票複製、= 1 退票改可寫;沒有 `VM_TICKET` → 照舊(一般配置複製,失敗回報)。
- **fork 時**,proc_mem 在持有 `p->mem.mx` 的情況下把 ANON 範圍描述(heap 的 `[USER_HEAP_BASE, brk)` 與 mmap 表)同步傳給 `vm_space_fork`;VM 依描述決定父的獨佔可寫頁變成 11(ANON)還是 10(legacy)。未兌現的 ANON 頁(沒有 PTE)也由這份描述得知數量。
- 驗收加一項:同一個位址空間裡同時有 ANON 與 legacy 的 COW 頁,各自走對的路徑,Σ 票核對一致。

## BR4. 一次完成的記帳交易(阻擋 4)

membudget 提供在 `mb_lk` 之內一次完成「多類別配額 + 實體預留」的介面(沿用 R2 的例外:`mb_lk` 之內只呼叫 pmm 的純記帳函式):

```c
struct mb_bundle {
    unsigned long quota[MB_NCLASS];   /* 各類別要增加的配額 */
    unsigned long reserve;            /* 要預留的實體頁 */
};
/* 在 mb_lk 之內:BR1 的配額檢查(加總)→ pmm_reserve(reserve) → 套用配額。
   任一步失敗:什麼都不改,回傳 -E_NOMEM。呼叫者必須已持有 vm_lk,並在同一段 vm_lk 之內
   更新空間帳本 — 對遵守完整鎖序的觀察者,三者同時生效 */
int  mb_commit_bundle(struct mb_domain *d, const struct mb_bundle *b, const struct mb_exec_txn *txn);
void mb_release_bundle(struct mb_domain *d, const struct mb_bundle *b);   /* 反向;超量 → 回傳值 / 計數 */
```

**fork 的兩筆帳分開**:父的新增票(父的獨佔 ANON 頁變成 COW 所需)只動實體預留,不動父的配額(那些頁早已算在父的 ANON 配額裡);子的是完整 bundle。順序:
1. 子 bundle(`mb_commit_bundle(C, ...)`)。
2. 父新增票(`pmm_reserve`,記在父空間帳本的「待生效」欄)。
3. 建子空間的表與 PTE。
4. 成功:把父的待生效票轉為正式,並把父的 PTE 改成 COW(不會失敗)。

任何一步失敗:**分別**退回 — 父的待生效票 `pmm_unreserve`、子空間 destroy(只退子的帳);destroy 子空間不會、也不能退父的票。

## BR5. 附帶修正

- **munmap 分段**:每段最多 64 頁,在 `vm_lk` 之內對每一頁同時處理 PTE、資料票、refcount;段與段之間 COW 快路徑仍可能發生(`p->mem.mx` 擋不住它),所以每一頁都在鎖內重新讀 PTE 再決定,不依賴段開始時的狀態。
- **sbrk**:票與配額只依「舊結尾與新結尾各自進位到整頁後的頁數差」增減;同一頁內移動 brk 不改帳。
- **頁表票的上限**:反覆 grow / shrink / mmap 會不斷申請 `pt_need`,而 munmap 不退頁表票。加上限:每個空間 `pt_tickets + 已建的 ANON 中間表 ≤ ANON_PT_MAX`(heap 256MB 與 mmap 240MB 範圍內最多可能的中間表數);承諾時只預留 `min(pt_need, ANON_PT_MAX − 現有)`。到達上限時,ANON 範圍內每一張可能的表不是已建就是已有票,所以不少預留也安全。
- **exec 接近配額上限**:(b1) 新空間的根表多記 1 頁 PGTABLE 配額,原本剛好能 exec 的情況可能提早被拒絕 — 寫進行為說明。
- **(b2)**:`thread_prepare` 之後只能呼叫一次 `thread_start` 或 `thread_abandon`;`name`、`arg`、domain 參考存活到 `thread_free`;KOBJ 以 `kmalloc_size()`(含標頭)取整。
